# Revue de correctness — 2026-10-23

> Ce document est le **compte rendu de la revue** demandée après la
> découverte répétée de bugs « par hasard », pendant d'autres tâches.
> Il dit **ce qui a été trouvé**, **ce qui a été reproduit**, **ce qui
> a été corrigé**, **ce qui a été mesuré**, et **ce qui reste ouvert**.
>
> Il n'est pas un rapport d'identifiants : chaque ligne de la section
> « bugs » a été **reproduite** sur le code d'avant le correctif, et
> chaque ligne de la section « tests » **échouerait** sur ce code.

## 1. La méthode

La revue a été menée en **lecture seule**, par domaine, avec des
auditeurs séparés (alpha-beta, MCTS, valeur apprise, core et UCI), pour
éviter l'angle mort d'une relecture monolithique. **Aucun rapport
d'auditeur n'a été cru sur parole** : les constats critiques et majeurs
ont été **rejoués** sur le code d'avant le correctif, avec le message
d'erreur exact.

Trois catégories, tenues séparées dans tout le document :

* **confirmé** — reproduit, corrigé, couvert par un test qui échoue
  sans le correctif ;
* **candidat** — plausible, non reproduit, **non corrigé** ;
* **fausse hypothèse** — une supposition de la revue qui s'est révélée
  fausse à la vérification (elle est documentée pour que personne ne
  la reprenne).

Le fil directeur des défauts : **presque tous sont des invariants qui
n'étaient écrits nulle part**. Le code était correct au sens de Rust ;
ce qui manquait, c'était la phrase « cette valeur doit être dans cette
échelle », « cette commande doit répondre », « cette position doit
être rendue égale à son miroir ».

## 3. Les fausses hypothèses (documentées pour ne pas les reprendre)

* **« La symétrie exacte de l'évaluation est la rotation de 180° »** —
  faux. La table est indexée dans le cadre « rang = `sq >> 3` » : les
  noirs lisent `PSTV[kind][sq]`, les blancs `PSTV[kind][sq ^ 56]`. La
  symétrie exacte est donc le **retournement vertical + échange des
  couleurs** ; la rotation de 180° n'est **pas** une symétrie (les
  tables PeSTO ne sont pas symétriques en fichiers : a2 et h2 diffèrent,
  l'écart mesuré est de 30 à 45 cp). *L'inverse* de cette hypothèse a
  été vérifié numériquement avant d'écrire le test.
* **« Le score de recherche doit s'inverser sur le miroir »** — faux :
  le score est **côté trait**. Sur le miroir (couleurs échangées), le
  camp au trait est l'autre camp : le score doit être **le même**
  (35 contre 35, et non 35 contre −35). L'anti-symétrie porte sur la
  valeur « Blanc positif » (`eval_white`), pas sur le score rendu.
* **« Le test de mat utilisait une position correcte »** — faux : le
  FEN `6k1/5ppp/8/8/8/8/8/R3R1K1 b - - 0 1` n'était pas un mat (les
  noirs ont `Kf8` et `Kh8`) ; c'est un **mat en un** pour les blancs.
* **« Les deux moteurs divergeaient sur la règle de répétition »** —
  faux : les deux implémentations utilisent la **même** règle (deux
  occurrences antérieures = trois au total). C'est le *test* qui
  ignorait la fenêtre des Fifty Moves : la répétition est bornée par
  l'horloge `halfmove` (une position ne peut se répéter que si aucune
  capture ni coup de pion n'a eu lieu depuis). Le MCTS applique la
  fenêtre, l'alpha-beta regarde les 100 dernières positions — les deux
  règles sont **équivalentes** (la même clé Zobrist implique la même
  pièce de pion, donc aucune capture ni coup de pion entre les
  occurrences).
* **« Le MCTS fait 0 nœud sur un `go` nu »** — le symptôme était le
  mien : en **pipeline**, l'EOF de l'entrée standard fait sortir la
  boucle UCI, qui arrête le worker. Le moteur, lancé par un arbitre
  (entrée ouverte), fait bien ses 10 000 nœuds.

## 5. Les mesures

### 5.1 La borne de quiescence (8 prises) est neutre en force

C'est le seul changement de la revue qui modifie **ce que le moteur
joue** ; il fallait donc le mesurer, pas le supposer.

* **Mesure statique** (10 positions, profondeur 5) : scores **identiques
  sur 9 positions** (+20 cp sur le kiwipete, la position la plus riche
  en promotions) ; **−35 % de nœuds** (422 210 contre 653 902).
* **Duel** (200 parties, 200 ms/coup, livre ECO, SPRT `elo0=0 elo1=5`) :
  **−6,95 ± 33,80 Elo**, LLR −0,10 — le SPRT **ne rejette pas** la
  borne. Verdict : **neutre en force**, et 35 % de nœuds en moins.

Log : `prt/rr/quiescence-borne.log` ; PGN : `prt/rr/quiescence-borne.pgn`.

### 5.2 Ce que la revue n'a pas pu mesurer

* **L'Elo de l'alpha-beta lui-même** : l'adversaire prévu (CAPS-LiTE)
  est hors service (« Engine caps is not responsive » puis
  « stalled / disconnected »), et aucun Stockfish local n'est
  disponible. Les duels contre CAPS-LiTE des phases précédentes
  restent donc **non jouables** en l'état.
* **La force de la valeur apprise** : le modèle `models/value_v1.bin`
  reste rejeté par son propre gate (−612 ± 99 Elo mesurés le
  2026-10-23). Il est livré sur le disque mais **n'est pas** l'option
  par défaut ; le gate d'entraînement n'empêche pas encore la
  livraison d'un modèle perdant (voir §6).

## 6. Ce qui reste ouvert

* **Le gate d'entraînement NN** n'empêche pas d'écrire **ni de livrer**
  un modèle mesurablement plus faible que l'évaluation statique. C'est
  le premier chantiers ouvert.
* **L'adversaire de duel** : CAPS-LiTE est injoignable ; il faut
  reconstruire le protocole (ou décider d'un autre adversaire) avant
  toute mesure d'Elo de l'alpha-beta.
* **La phase générateur G4** reste incomplète ; le gate « après vs
  avant » a produit 400–0, un résultat **suspect** (le binaire de
  référence a été construit 13 secondes avant le nouveau : G2 et G3 ne
  sont pas isolés).
* **Évaluation** : le roi en échec n'est ni détecté ni pénalisé ; la
  valeur du roi n'est pas graduée (une table de fin de partie
  manquante) ; la symétrie de l'évaluation n'est pas symétrique en
  fichiers (c'est documenté, c'est assumé).
* **MCTS** : la terminalité en mode parallèle et le budget temporel
  multi-threads restent à auditer en détail (l'arène indexée et le
  partage de l'arbre par les workers sont sûrs, mais le chemin
  mono/parallel n'a pas la même garantie de terminalité).
* **Structure** : `src/ab/search.rs` dépasse 1 100 lignes et a reçu de
  nouvelles fonctions ; les invariants gagneraient à être extraits dans
  un module cohérent plutôt plutôt qu'à continuer d'agrandir le fichier.

## 7. Ce que la revue ne dit pas

Elle ne dit pas que le moteur est **correct**. Elle dit que les
invariants **connus** sont maintenant **écrits**, et donc que la
prochaine découverte par hasard sera moins chère : elle aura un test
qui échoue à côté.
